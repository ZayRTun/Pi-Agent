# Domain Docs

This is a single-context repository.

## Before exploring

- Read `CONTEXT.md` at the repository root.
- Read relevant ADRs under `docs/adr/`.

## Vocabulary

Use the glossary's canonical vocabulary in specs, issue titles, test names, and implementation discussions. If a needed concept is missing, use `/domain-modeling` to resolve it before inventing terminology.

## ADR conflicts

If a proposed change contradicts an existing ADR, surface the conflict explicitly instead of silently overriding the decision.

## Layout

- `CONTEXT.md` — project glossary
- `docs/adr/` — architectural decisions
